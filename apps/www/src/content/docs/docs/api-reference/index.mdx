The TypeScript SDK is the recommended integration. For direct HTTP clients, every request uses HTTPS,
JSON, and a server-side secret key.

## Authentication

```http
Authorization: Bearer sk_test_replace_with_your_key
Content-Type: application/json
```

Never send secret keys from a browser. A key is scoped to one application environment.

## Primary endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/message-deliveries` | Send a published definition |
| `GET` | `/v1/message-deliveries/{id}` | Retrieve a managed delivery |
| `POST` | `/v1/sms/messages` | Send direct SMS |
| `POST` | `/v1/sms/batches` | Submit 1–100 SMS items |
| `GET` | `/v1/sms/{id}` | Retrieve direct SMS |
| `POST` | `/v1/email/messages` | Send direct email |
| `GET` | `/v1/email/messages/{id}` | Retrieve email |
| `POST` | `/v1/verify` | Start a verification |
| `POST` | `/v1/verify/check` | Check a verification code |
| `GET` | `/v1/wallet` | Read the environment wallet |
| `GET` | `/v1/webhooks` | List webhook endpoints |
| `POST` | `/v1/webhooks` | Create a webhook endpoint |

## Idempotent writes

Managed sends and batch sends require an `Idempotency-Key` header. Reuse the same value only for an
identical logical operation. Reusing it with a different payload returns a stable conflict error.

```http
Idempotency-Key: order-shipped:GH-4821
```

## Errors

Errors use a JSON envelope with a stable machine-readable `code`. Branch on the HTTP status and code,
not the message text.

```json
{
  "error": {
    "code": "idempotency_key_required",
    "message": "An Idempotency-Key header is required."
  }
}
```

The committed, machine-readable specification ships with the SDK at
`@fabric-messaging/sdk/openapi.json`.
