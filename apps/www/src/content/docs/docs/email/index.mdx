Send direct email when your server already owns the rendered subject and body. Use a
[message definition](/docs/email/templates/) when non-developers should change the content without a
deploy.

## Send

```ts
const response = await fabric.email.send(
  {
    to: "ama@example.com",
    from: "receipts@your-domain.example",
    replyTo: "support@your-domain.example",
    subject: "Receipt for order GH-4821",
    text: "Thanks Ama. Your payment was received.",
    html: "<p>Thanks Ama. Your payment was received.</p>",
  },
  { idempotencyKey: "receipt:GH-4821" },
);

console.log(response.data.id, response.data.status);
```

At least one of `text` or `html` is required. Supplying both gives clients a safe plain-text fallback
and improves deliverability. An idempotency key is optional but recommended so a retry does not send
twice.

## Retrieve and list

```ts
const message = await fabric.email.retrieve(response.data.id);
console.log(message.data.status, message.data.errorCode);

const recent = await fabric.email.list();
```

`retrieve` returns the `EmailMessage` — `status`, `from`, `subject`, `provider`, and a nullable
`errorCode`. `list` returns recent messages for the key's environment.

:::caution[Authenticate your domain before going live]
Sandbox email uses a fake provider and never reaches a real inbox. Do not use a live `from` address
until its domain is configured and verified — unauthenticated mail is filtered or rejected.
:::
