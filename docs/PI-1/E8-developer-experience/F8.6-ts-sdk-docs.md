# F8.6 — TypeScript SDK + developer portal (basic)

**Epic:** E8 DX · **Priority:** MUST-basic · **Iteration:** 5
**Depends on:** F8.1–F8.5 · **Blocks:** developer adoption

## Why
Time-to-first-successful-call is the real sales funnel. DX is the wedge the African incumbents left
open (no CLI, weak docs, key-in-body auth). Ship a great first SDK + docs.

## Stories
- **US-8.6.1** — As a **developer**, a TypeScript SDK lets me integrate quickly with typed methods and errors.
- **US-8.6.2** — As a **developer**, the dev portal lets me manage keys, read docs with my own test keys inlined, see usage logs, and test a webhook.

## Acceptance criteria
- [ ] **TypeScript/Node SDK** covering send, verify, wallet, webhooks; typed errors; idempotency support.
- [ ] Dev portal: **API key management**, **usage logs**, **docs** with copy-paste examples (test keys inlined), and a **webhook tester** (send a sample signed event).
- [ ] Quickstart that gets a developer to a first successful test send fast.
- [ ] Magic-number table + error reference published.

## Design notes
- **PI-2:** CLI (`listen/forward/trigger/replay`), multi-language SDKs (PHP/Python/Java), interactive API explorer.

## Out of scope (this PI)
- CLI; additional language SDKs; fully interactive API console.

## Definition of Done
- SDK published + smoke-tested against sandbox; portal key-mgmt + webhook tester working; quickstart validated.
