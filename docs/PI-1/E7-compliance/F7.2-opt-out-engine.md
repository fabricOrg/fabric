# F7.2 — Opt-out / STOP engine

**Epic:** E7 Compliance · **Priority:** MUST · **Iteration:** 3 · ★ legally mandatory
**Depends on:** F5.1, F7.1 · **Blocks:** F5.2 (suppression check)

## Why
Honoring STOP and DND is **law**, not a feature (Nigeria NCC 2442; fines up to ₦10M / 2% revenue).
A send to an opted-out recipient must be blocked before it goes out.

## Stories
- **US-7.2.1** — As an **end recipient**, replying STOP permanently stops messages from that sender, so my consent is respected.
- **US-7.2.2** — As the **platform**, every outbound send checks the suppression list first, so we never message an opted-out person.
- **US-7.2.3** — As a **tenant**, DND-registered numbers are routed/handled per country rules, so my traffic stays compliant.

## Acceptance criteria
- [ ] Inbound **STOP/UNSUBSCRIBE/CANCEL/…** adds the recipient to a **tenant-scoped suppression list**; **START** removes; **HELP** returns info (no list change).
- [ ] **Every send checks suppression before reserve** (F5.2); a blocked send fails with a defined error (our analog of Twilio 21610) and is **not billed**.
- [ ] Default keyword set + tenant-customizable keywords + confirmation messages.
- [ ] **DND-aware routing** flag per country (Nigeria 2442; `dnd`-channel concept) on the provider.
- [ ] Messages carry a **classification** (`transactional | promotional`); promotional traffic respects consent/DND while transactional (e.g. OTP) may use the DND route — classification drives routing + consent rules.
- [ ] Consent state recorded against the `subject_id` (F7.1).
- [ ] Test: STOP → subsequent send blocked + unbilled; START re-enables; suppression checked on bulk too.

## Design notes
- Inbound STOP requires the minimal inbound-ingest path (webhooks-ingress).
- Suppression is consent data → stored against the data subject.

## Out of scope (this PI)
- Full per-country compliance rule engine; category (partial) DND codes.

## Definition of Done
- STOP/START/HELP tests; pre-send suppression block (single + bulk); unbilled-on-block.
