# F2.1 — Customer SSO (WorkOS AuthKit)

**Epic:** E2 Identity · **Priority:** MUST · **Iteration:** 1–2
**Depends on:** F1.1 · **Blocks:** dashboard, F7.6 (tenant onboarding)

## Why
One login for every current and future app; centralized day one because SSO can't be retrofitted.
(`IDENTITY-SSO.md`.)

## Stories
- **US-2.1.1** — As a **new business user**, I can self-sign-up and get my own organization, so I can start without sales contact.
- **US-2.1.2** — As a **tenant admin**, MFA is enforced on my account, so privileged access is protected.
- **US-2.1.3** — As a **user**, after logging in once I can open another of the platform's apps without logging in again.

## Acceptance criteria
- [ ] Self-serve sign-up via hosted AuthKit; email verification.
- [ ] First login **JIT-provisions** a local `users` row keyed by the WorkOS `sub`; a no-invite signup **creates a new org and makes the user its owner** (invited users attach to the inviting org instead).
- [ ] **MFA mandatory for owner/admin** roles (enrollment gate before privileged access); optional for members.
- [ ] Tokens are held **server-side by the BFF**; the browser only gets an **httpOnly** session cookie (no JWT in JS).
- [ ] Opening a second app redirects to the same AuthKit session → **no re-login** (silent SSO).
- [ ] Active org + role available to the app from validated session claims (`org_id`, `role`).
- [ ] **WorkOS inbound webhooks** (`user.created`, `organization_membership.created`, etc.) are received (signature-verified) and keep local `users`/`accounts`/`memberships` in sync; handler is idempotent.

## Design notes
- BFF: `getAuthorizationUrl` → `authenticateWithCode` (seal session) → `authenticateWithSessionCookie` (validate, no network).
- Local Postgres remains source of truth for tenancy/billing; sync via JIT + WorkOS webhooks.
- Implementation note (2026-07-04): hosted AuthKit documents global and organization-wide MFA
  enforcement, not role-specific enforcement. The owner/admin-only requirement needs either
  organization-wide MFA as a stronger policy or a custom factor enrollment/challenge flow.

## Out of scope (this PI)
- Enterprise SAML/SCIM connections; org-switching UX polish.

## Definition of Done
- E2E: signup → org+owner → MFA enrol → silent SSO into a second app; no token in browser storage.
