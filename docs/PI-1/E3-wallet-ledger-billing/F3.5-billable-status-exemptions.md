# F3.5 — Billable-status set + platform-fault exemptions

**Epic:** E3 Wallet · **Priority:** MUST · **Iteration:** 2–3
**Depends on:** F3.2, F5.3 · **Blocks:** correct commit/refund

## Why
Honest, margin-safe billing: charge the customer on the **same basis the provider bills us**, and
**never charge for failures the platform caused**. (Refined from research — Twilio bills
`undelivered` + a `failed` fee but exempts its own faults.)

## Stories
- **US-3.5.1** — As a **tenant**, I'm never charged for a message that failed due to a fault on the platform's side, so billing is fair.
- **US-3.5.2** — As the **platform**, the charge timing mirrors exactly what the provider bills us, so there's no phantom charge and no margin gap.

## Acceptance criteria
- [ ] Each provider instance declares **`billableStatuses[]`** and a **`platformFaultExemptions[]`** list (internal_error, suspension, fraud_block, geo_block).
- [ ] Reservation **commits** when the message reaches a billable status; **refunds** on a platform-fault exemption or non-billable terminal status.
- [ ] Pre-submission failures (invalid number, no route) always refund.
- [ ] The applied billing decision is recorded on the message + usage record for transparency.
- [ ] Test: each (status × provider config) maps to the correct commit/refund; exemptions always refund.

## Design notes
- Replaces the earlier binary `billingBasis: submission|delivered` (too clean for real providers).
- Drives F3.2 commit/refund; surfaced in cost-per-delivered reporting.

## Out of scope (this PI)
- "Guaranteed-delivered" premium billing tier (priced ≥ cost ÷ delivery_rate) — fast-follow.

## Definition of Done
- Status→billing decision table tested per provider; exemptions verified to refund.
