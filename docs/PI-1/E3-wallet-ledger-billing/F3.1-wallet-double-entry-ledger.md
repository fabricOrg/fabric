# F3.1 — Wallet + double-entry ledger

**Epic:** E3 Wallet · **Priority:** MUST · **Iteration:** 2 · ★ crown jewel
**Depends on:** F1.1 · **Blocks:** F3.2–F3.7, F4.2, F5.2

## Why
Money correctness is the hardest, most valuable part. Balance must be **derived** from an immutable
ledger, never a mutable counter. (`ARCHITECTURE.md §5`; Modern Treasury best-practice.)

## Stories
- **US-3.1.1** — As a **tenant**, my wallet balance always equals the sum of my recorded transactions, so I can trust it absolutely.
- **US-3.1.2** — As the **platform**, every money movement is an immutable double-entry record, so it's architecturally impossible to lose track of money.

## Acceptance criteria
- [ ] One wallet per **`(tenant_id, currency)`** (`UNIQUE`); money in **bigint minor units** (never float).
- [ ] `ledger_entries` are **append-only**; a transaction is `pending` then `posted`; corrections are **compensating entries**, never edits/deletes.
- [ ] Wallet `balance_minor` is a **cached projection** rebuildable from entries.
- [ ] Every entry references `subject_id` surrogates where PII is involved (never raw PII — F7.1).
- [ ] **Invariant** (CI + scheduled, F1.5): per wallet, `Σcredits − Σdebits = balance_minor`.
- [ ] Test: balance can be fully reconstructed from `ledger_entries` alone.

## Design notes
- `ledger_transactions` header (carries idempotency key + type) + `ledger_entries` legs.
- Categories: `topup | sms_charge | adjustment | refund` (Africa's Talking-style vocabulary).
- Multi-currency machinery built now; enabled set is config (F3.6); FX deferred (single-currency per txn).

## Out of scope (this PI)
- FX / cross-currency transactions; `fx_rates` table not created yet.

## Definition of Done
- Reconstruct-from-entries test; invariant job green; no mutable-balance UPDATE outside the projector.
