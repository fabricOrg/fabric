# F3.4 — Rating + usage records

**Epic:** E3 Wallet · **Priority:** MUST · **Iteration:** 2
**Depends on:** F3.1, F3.6 · **Blocks:** F5.2 (rate step), billing transparency

## Why
Customers must see *what they paid for*, itemized. Twilio's UsageRecords model (quantity/unit/
price/currency/category) is the transparency bar.

## Stories
- **US-3.4.1** — As a **developer/tenant**, I can see itemized usage (per message: segments × unit price, currency), so my bill is transparent and auditable.
- **US-3.4.2** — As the **engine**, I can compute a send's cost from a price list before reserving funds.

## Acceptance criteria
- [ ] `RatingService.rate(segments, destination, currency)` returns a cost from **`price_lists`** (per product · country/prefix · currency).
- [ ] Each charge writes a **`usage_record`**: `quantity`, `unit`, `unit_price_minor`, `total_minor`, `currency`, `category`, `reference_id`.
- [ ] **Provider cost is captured** alongside the customer charge (`provider_cost_minor`) so **margin** and **true cost-per-delivered** are computable (feeds the positioning wedge + F9.5).
- [ ] Usage is queryable **per tenant** and aggregatable by period.
- [ ] Pricing currency must be one of the enabled currencies (F3.6); unknown destination → clear error.
- [ ] Test: rating math (segments × price) and currency selection; usage record written on every charge.

## Design notes
- Price lists authored in the control plane (F9.1), platform-default + optional per-tenant override.
- Feeds the "cost-per-delivered" reporting (positioning wedge).

## Out of scope (this PI)
- Volume/committed-tier pricing; invoices.

## Definition of Done
- Rating unit tests across currencies/destinations; usage-record coverage on charges.
