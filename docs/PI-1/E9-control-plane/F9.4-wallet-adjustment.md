# F9.4 — Wallet adjustment (maker-checker)

**Epic:** E9 Control Plane · **Priority:** MUST · **Iteration:** 5
**Depends on:** F3.1, F1.4, F2.2 · **Blocks:** support/finance ops

## Why
Operators sometimes must credit/debit a wallet (goodwill, correction, refund). Money operations need
**dual control** and audit so no single operator can move funds unchecked.

## Stories
- **US-9.4.1** — As a **finance operator**, I can post an audited manual wallet adjustment, so I can correct balances or issue goodwill credit.
- **US-9.4.2** — As a **platform owner**, money adjustments require a second approver, so no single person can move funds alone.

## Acceptance criteria
- [ ] An adjustment is posted as a **ledger entry** (F3.1) with category `adjustment`, reason, and reference.
- [ ] **Maker-checker**: a second authorized operator must approve before it posts; **step-up auth** required (F2.2).
- [ ] Fully **audited** (maker, checker, reason, before/after) (F1.4).
- [ ] Adjustments respect the ledger invariant (F1.5).
- [ ] Test: single-operator cannot post; two-operator flow posts + audits; invariant stays green.

## Design notes
- Goes through the same immutable ledger — adjustments are compensating entries, never edits.

## Out of scope (this PI)
- Bulk adjustments; approval-policy configurability.

## Definition of Done
- Maker-checker enforced; adjustment audited; invariant holds.
