# F9.2 — Tenant inspection (support)

**Epic:** E9 Control Plane · **Priority:** MUST · **Iteration:** 5
**Depends on:** F2.2 · **Blocks:** support operations

## Why
Support needs to see a tenant's messages, wallet, and ledger to diagnose issues — read-only, scoped,
and audited.

## Stories
- **US-9.2.1** — As a **support operator**, I can look up a tenant and view their messages, wallet balance, and ledger, so I can resolve tickets.

## Acceptance criteria
- [ ] Operator search by tenant; view messages (status, cost), wallet balance, ledger entries, usage records.
- [ ] PII is shown only per access policy; viewing PII is **audited** (F1.4).
- [ ] Read-only (mutations go through guarded actions like F9.4); RBAC-gated (F2.2).
- [ ] Test: support role can view but not mutate; PII access audited.

## Design notes
- Resolves PII via the vault (F7.1) under access policy; consider redaction by default with explicit reveal.

## Out of scope (this PI)
- Impersonation (time-boxed) — consider PI-1 stretch per §16 decision; otherwise PI-2.

## Definition of Done
- Read-only inspection tested; PII-view audit; RBAC enforced.
