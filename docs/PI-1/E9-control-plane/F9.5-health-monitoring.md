# F9.5 — Health & DLR-trust dashboard

**Epic:** E9 Control Plane · **Priority:** MUST · **Iteration:** 5
**Depends on:** F1.5, F5.4, F7.5 · **Blocks:** —

## Why
Operators need one read-only view of system + provider health, and crucially the **DLR-trust** signal
(real vs reported delivery) — our reliability differentiator.

## Stories
- **US-9.5.1** — As an **operator**, I see system health (throughput, queue depth, error rates) and per-provider delivery quality at a glance.
- **US-9.5.2** — As an **operator**, I see each route's **DLR-trust score** (probed vs reported delivery), so I can spot fake-DLR routes.

## Acceptance criteria
- [ ] Read-only dashboard: send throughput, accept/deliver/fail rates per provider, queue depth, reconciliation drift, open reservations (F3.3).
- [ ] **Per-route DLR-trust score** + divergence alerts (F7.5).
- [ ] **Ledger-invariant status** surfaced (F1.5).
- [ ] Consumes metrics/events; **never in the data-plane hot path**.
- [ ] Test: dashboard reflects seeded metrics; a low-trust route is flagged.

## Design notes
- Pure consumer of telemetry (F1.5) + DLR-trust (F7.5) + reservation metrics (F3.3).

## Out of scope (this PI)
- Full SLO/incident tooling; alerting workflows (PI-2).

## Definition of Done
- Dashboard renders health + trust + invariant; low-trust flag verified.
