# F9.3 — Sender-ID approval queue

**Epic:** E9 Control Plane · **Priority:** MUST · **Iteration:** 5
**Depends on:** F7.3, F2.2 · **Blocks:** F7.3 lifecycle

## Why
Sender-ID approval is operator-driven and multi-day; operators need a queue to review and set
per-country/operator approval state.

## Stories
- **US-9.3.1** — As an **operator**, I review pending sender-ID requests with their docs and approve/reject per country, so tenants can send on compliant IDs.

## Acceptance criteria
- [ ] Queue of pending sender-ID requests with submitted details/docs.
- [ ] Approve/reject **per country/operator**; state flows back to `sender_ids` (F7.3).
- [ ] Decisions are **audited** (actor, reason) (F1.4); tenant notified on state change.
- [ ] Test: approving updates state → sends allowed for that country; rejecting blocks with reason.

## Design notes
- PI-1 = manual review workflow; automated MNO submission APIs are later.

## Out of scope (this PI)
- Automated carrier submission; SLA timers.

## Definition of Done
- Approve/reject updates state + audit + notification; gating verified against F7.3.
