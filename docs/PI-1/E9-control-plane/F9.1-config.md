# F9.1 — Config (currencies, pricing, providers)

**Epic:** E9 Control Plane · **Priority:** MUST · **Iteration:** 5
**Depends on:** F2.2 · **Blocks:** F3.4, F3.6, F5.1

## Why
Operators must configure the platform without deploys — currencies, price lists, and which provider
instances are live. Config is authored here; the data plane reads it cached (never in the hot path).

## Stories
- **US-9.1.1** — As an **operator**, I set enabled currencies + default, so launching a market is a config change.
- **US-9.1.2** — As an **operator**, I manage price lists per product/destination/currency, so rating is correct.
- **US-9.1.3** — As an **operator**, I enable/disable provider instances + credentials, so I control routing without code.

## Acceptance criteria
- [ ] Manage **enabled currencies + default** (F3.6); **price lists** (F3.4); **provider instances** (enable/disable, credentials ref, config).
- [ ] All config changes are **validated**, **versioned**, and **audited** (F1.4); applied without deploy.
- [ ] Data plane reads config from a **cached, last-known-good** store; keeps serving if the control plane is down.
- [ ] Test: a config change propagates to the data plane; an invalid config is rejected; change is audited.

## Design notes
- Config-as-data; the precedence ladder (platform default → tenant → request) is the delegation model.
- Staged rollout/rollback = fast-follow; PI-1 = validated + versioned + audited.

## Out of scope (this PI)
- Canary/staged config rollout; entitlements UI.

## Definition of Done
- Propagation + validation + audit tests; data-plane reads cached config.
