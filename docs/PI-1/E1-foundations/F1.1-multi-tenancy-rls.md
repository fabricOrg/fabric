# F1.1 — Multi-tenancy + Row-Level Security

**Epic:** E1 Foundations · **Priority:** MUST · **Iteration:** 1 · **Status:** Ready
**Depends on:** — · **Blocks:** everything (every table is tenant-scoped)

## Why
Hard tenant isolation is the bedrock of a multi-tenant platform; an app-layer bug must never leak
one customer's data to another. (`ARCHITECTURE.md §2`.)

## Stories
- **US-1.1.1** — As a **tenant**, my data is fully isolated, so no other tenant can ever read or write it.
- **US-1.1.2** — As a **platform** engineer, every query is auto-scoped to the caller's tenant, so a missing `WHERE tenant_id` can't cause a cross-tenant leak.

## Acceptance criteria
- [ ] Every business table carries a non-null `tenant_id`.
- [ ] A single **tenant context** is resolved once per request (from API key or session) and carried through the request lifecycle.
- [ ] **Two DB roles (B4):** a **migration/owner role** (owns tables) and a **runtime app role** that is **not** the owner and lacks `BYPASSRLS`. Every tenant table has RLS **enabled AND `FORCE ROW LEVEL SECURITY`** (so the owner is constrained too). App traffic connects only as the runtime role.
- [ ] **Pooling-safe tenant context (B3 — highest blast radius):** decided pooling mode = **transaction pooling (RDS Proxy / PgBouncer)**. Therefore **every tenant-scoped operation runs inside a `db.transaction()` whose first statement is `SET LOCAL app.tenant_id = $1`**. Plain `SET` (session-scoped) is **forbidden** (lint-enforced) because it leaks across pooled checkouts.
- [ ] RLS policies read `current_setting('app.tenant_id')`; a query without it (or with a forged different id) returns **0 rows**.
- [ ] Repository/data layer **requires** a tenant scope — no code path issues an unscoped query, and no path runs a tenant query outside a `SET LOCAL` transaction (lint/test enforced).
- [ ] **Control-plane cross-tenant reads** (admin) use a **separate, explicitly-policied, audited code path** — never an implicit owner/superuser bypass.
- [ ] Test: Tenant A cannot read/update/delete any Tenant B row via any endpoint; **two tenants interleaved on the same pooled connection show zero leakage** (the B3 regression test); a forged `tenant_id` returns 0 rows.

## Design notes
- Shared DB, shared schema, `tenant_id` per row; RLS = defense-in-depth behind app-layer scoping.
- `SET LOCAL` is transaction-scoped — that is *why* every tenant op must be wrapped in a transaction under transaction-mode pooling (B3). This pattern must be baked into the data layer **before the first migration**, since the regression test must exist before any tenant query is written.
- Escape hatch for future enterprise isolation = dedicated single-tenant deployment (same code).

## Out of scope (this PI)
- Per-tenant physical isolation / dedicated deployments.

## Definition of Done
- RLS cross-tenant test + **interleaved-pool leakage test** in CI; `FORCE RLS` on all tenant tables; runtime role is non-owner/non-BYPASSRLS; no unscoped-query and no bare-`SET` lint violations.
