# F1.5 — Observability + ledger-invariant job

**Epic:** E1 Foundations · **Priority:** MUST · **Iteration:** 1
**Depends on:** F1.1 · **Blocks:** F9.5 health dashboard

## Why
We can't operate a money + delivery system blind. The **ledger-invariant job** is the single most
important alarm — it proves money correctness continuously.

## Stories
- **US-1.5.1** — As an **operator**, I can trace a request end-to-end (edge → engine → provider → DLR) by one `trace_id`, so I can diagnose issues fast.
- **US-1.5.2** — As the **platform**, a scheduled job verifies money correctness and pages on drift, so silent ledger corruption is caught immediately.

## Acceptance criteria
- [ ] Structured JSON logs carry `tenant_id` + `request_id` (+ `trace_id`) on every line.
- [ ] Distributed tracing (OpenTelemetry) spans the request path.
- [ ] Core metrics emitted: send throughput, accept/deliver/fail rates per provider, queue depth, wallet-reservation latency, reconciliation drift.
- [ ] **Ledger-invariant job** runs on a schedule and asserts, per wallet, `Σcredits − Σdebits = balance`; any mismatch raises an alert.
- [ ] **No raw PII in logs/traces/errors:** logs, spans, and error payloads (incl. `param`, F8.3) must reference `subject_id` — **never** a raw phone number or message body. A redaction/scrubbing layer enforces this; error messages echo identifiers, not PII.
- [ ] Test: an intentionally corrupted balance is detected by the invariant job; a send with an invalid number produces logs/error containing **no raw phone number** (asserted by a PII-scan test).

## Design notes
- Concrete o11y stack (Grafana/Prometheus/Loki vs Datadog vs Sentry) is a near-term pick — see open decisions.
- Metrics + events feed the control-plane health view (F9.5), consume-only.

## Out of scope (this PI)
- Full SLO/alerting maturity, incident tooling (PI-2).

## Definition of Done
- Invariant job in CI + scheduled in env; trace propagation verified across one full send.
