# F6.2 — OTP body redaction

**Epic:** E6 OTP/Verify · **Priority:** MUST · **Iteration:** 4
**Depends on:** F6.1, F7.4 · **Blocks:** —

## Why
OTP codes are sensitive secrets; storing them post-send is a needless breach risk. Always redact.

## Stories
- **US-6.2.1** — As a **compliance officer**, OTP message bodies are never persisted in readable form, so a data exposure can't leak live codes.

## Acceptance criteria
- [ ] Verify-generated messages **never write a body to the `pii_vault`** (forced `redact=true`).
- [ ] The code itself is stored only as a **hash** (for `check`), never plaintext (F6.1).
- [ ] Redaction is unconditional for Verify — not dependent on tenant `store_message_bodies`.
- [ ] Test: after a verify send, no readable OTP body or plaintext code exists in storage.

## Design notes
- Reuses the message-body redaction path (F7.4); Verify hard-codes redaction on.

## Definition of Done
- Storage-inspection test confirms no plaintext code/body for Verify messages.
