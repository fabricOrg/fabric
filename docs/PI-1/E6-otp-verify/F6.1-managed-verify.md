# F6.1 — Managed Verify

**Epic:** E6 OTP/Verify · **Priority:** MUST · **Iteration:** 4 · ★ high-margin
**Depends on:** F5.2 · **Blocks:** F6.2, F6.3

## Why
OTP is the highest-margin CPaaS use case (Termii's whole business). Ship a **managed** verify
service — code gen, expiry, attempt limits, fraud — so the customer writes almost no code, billed
**per successful verification**.

## Stories
- **US-6.1.1** — As a **developer**, I call `start` then `check` to verify a phone number, so I don't build code generation, expiry, or attempt limiting myself.
- **US-6.1.2** — As a **tenant**, I'm billed per successful verification, so pricing matches the value delivered.

## Acceptance criteria
- [ ] `POST /v1/verify` (start) generates a code, sends via SMS (channel pluggable later), returns a verification id.
- [ ] `POST /v1/verify/check` validates code; returns approved/denied.
- [ ] Configurable **code length (4–10)**, **expiry (~10 min)** (re-request inside window returns the same token), **attempt limit (~5 / 10 min)** per recipient.
- [ ] **Atomic attempt counting (B9):** each `check` increments and tests the counter **atomically** — either `SELECT … FOR UPDATE` on the `otp_request` row (increment + check in one transaction) or an atomic Redis `INCR` with the limit checked on the returned value. Concurrent guesses **cannot** all pass the cap. Code comparison is **constant-time**.
- [ ] **Success-based billing**: charge per successful verification (+ underlying channel/SMS cost) — distinct from a raw send (F3.4).
- [ ] OTP bodies are **always redacted** (F6.2).
- [ ] Test: happy verify; expiry; attempt-limit lockout; **N concurrent guesses never exceed the cap (B9)**; re-request returns same token in window.

## Design notes
- Built on the send pipeline (F5.2) but as a constrained, managed flow.
- Channel fallback (SMS→voice→WhatsApp) is **PI-2** (F6.4).

## Out of scope (this PI)
- Voice/WhatsApp/email channels; silent network auth.

## Definition of Done
- Verify E2E (start/check) via FakeProvider; expiry + attempt-limit + success-billing tests.
