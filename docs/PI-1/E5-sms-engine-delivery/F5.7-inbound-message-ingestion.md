# F5.7 — Inbound message ingestion (MO)

**Epic:** E5 SMS · **Priority:** MUST · **Iteration:** 3
**Depends on:** F5.1, F7.1 · **Blocks:** F7.2 (opt-out STOP)

## Why
Opt-out (F7.2) requires receiving inbound (mobile-originated) messages to detect STOP — but no story
owned the inbound path. This builds it: the minimal MO ingestion that F7.2 routes from.

## Stories
- **US-5.7.1** — As the **platform**, inbound messages from providers are received, verified, normalized, and routed, so STOP keywords are actioned and inbound is extensible later.
- **US-5.7.2** — As an **end recipient**, my reply (e.g. STOP) is reliably ingested and acted on.

## Acceptance criteria
- [ ] `webhooks-ingress` accepts provider **inbound (MO) callbacks** with **signature verification** per provider.
- [ ] Plugin contract gains **`parseInbound(payload) → CanonicalInbound`**; vendor shapes never reach the core.
- [ ] Inbound is normalized (E.164), the sender stored as **`subject_id`** (F7.1), and **routed to the opt-out engine** (F7.2) for keyword handling.
- [ ] Inbound persisted (status `received`) for audit/troubleshooting; emits an `inbound.received` event (F1.2).
- [ ] Idempotent on provider message id (duplicate inbound = one record).
- [ ] Test: a STOP inbound is ingested → suppression updated (F7.2); duplicate inbound deduped; bad signature rejected.

## Design notes
- PI-1 scope = ingest + STOP routing + audit. **Two-way conversations / inbound→tenant-webhook forwarding = PI-2.**

## Out of scope (this PI)
- Two-way messaging product, auto-replies, inbound→tenant webhook delivery.

## Definition of Done
- Inbound STOP E2E updates suppression; dedupe + signature tests green.
