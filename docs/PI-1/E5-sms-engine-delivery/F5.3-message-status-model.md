# F5.3 — Normalized message-status model

**Epic:** E5 SMS · **Priority:** MUST · **Iteration:** 3
**Depends on:** F5.1 · **Blocks:** F3.5 billing, F5.4 DLR

## Why
A canonical status enum is the contract every provider maps onto — the basis for billing decisions,
SLA observability, and the customer-facing status.

## Stories
- **US-5.3.1** — As a **developer**, every message has a consistent lifecycle status regardless of which provider delivered it.
- **US-5.3.2** — As the **platform**, each provider's raw status maps to our canonical enum, decoupling billing/observability from vendors.

## Acceptance criteria
- [ ] Canonical statuses: `queued → sending → accepted → sent → delivered | undelivered | failed` (+ `expired`); terminal set = {delivered, undelivered, failed, expired}.
- [ ] **`accepted`** = the provider acknowledged receipt (synchronous `send()` ProviderResult returned a ref). `sent` = the provider reports it onward to the carrier/MNO. These are distinct points in time. *(B1)*
- [ ] **The commit point is explicitly defined per provider** via `billableStatuses[]` (F5.1): the wallet charge commits when the message *first reaches* any status in that set (typically `accepted` for submission-billed, `delivered` for delivery-billed). Documented in the provider's mapping table.
- [ ] Each provider adapter maps its raw statuses + **error codes** onto the canonical enum; the **first real provider's full mapping table is written in this story** (not deferred).
- [ ] Status transitions are persisted with timestamps (`accepted_at`, `sent_at`, `delivered_at`) and are **monotonic** (a later out-of-order lower status never overwrites a terminal one — see F5.4).
- [ ] Canonical `error_code` taxonomy for undelivered/failed.
- [ ] Test: provider raw-status → canonical mapping table covered; illegal/backward transitions rejected; commit point fires exactly once at the configured status.

## Design notes
- Mirrors Twilio's lifecycle but adds an explicit `accepted` so billing has an unambiguous commit trigger (B1).
- Drives F3.5 (billable vs exempt) and F5.4 reconciliation. Exposed via `GET /v1/sms/:id` and webhooks (F8.4).

## Out of scope (this PI)
- WhatsApp `read` / inbound `received` richness (later channels).

## Definition of Done
- Mapping + transition tests; state machine documented.
