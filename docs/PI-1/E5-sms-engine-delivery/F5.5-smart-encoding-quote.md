# F5.5 — Smart-encoding warning / segment quote

**Epic:** E5 SMS · **Priority:** MUST · **Iteration:** 3
**Depends on:** F5.2 · **Blocks:** —

## Why
A single emoji can silently double or triple a message's cost (UCS-2 flip). Surfacing segment count
+ encoding protects customers from bill shock and protects our support load.

## Stories
- **US-5.5.1** — As a **developer**, the API tells me how many segments and which encoding a message will use, so I can predict cost before sending.
- **US-5.5.2** — As a **tenant**, I'm warned when non-GSM characters inflate my segment count.

## Acceptance criteria
- [ ] Send response (and a dry-run/preview endpoint) returns `encoding`, `segments`, and computed `cost`.
- [ ] A warning flag is set when a non-GSM character forced a UCS-2 encoding (cost inflation).
- [ ] Segment math matches F5.2 (GSM-7 153 / UCS-2 67 concatenated).
- [ ] Test: ASCII vs unicode payloads return correct segments + warning flag.

## Design notes
- Pure function reused by rating (F3.4) and the dashboard composer (later).

## Out of scope (this PI)
- Auto-transliteration / "smart encoding" character substitution.

## Definition of Done
- Segment/encoding/warning unit tests; preview endpoint returns quote.
