# F5.1 — SMS plugin contract + adapter + FakeProvider

**Epic:** E5 SMS · **Priority:** MUST · **Iteration:** 3
**Depends on:** F1.1 · **Blocks:** F5.2, F8.5 test mode

## Why
The anti-lock-in seam: every gateway is an adapter behind one canonical contract, so the core never
sees vendor shapes and providers are swappable. (`INTEGRATIONS-PLUGIN-ARCHITECTURE.md §3`.)

## Stories
- **US-5.1.1** — As the **platform**, all providers implement one `SmsSenderPlugin` contract, so adding/removing a vendor is a localized change.
- **US-5.1.2** — As a **developer**, a `FakeProvider` lets me (and CI) exercise the full send + DLR path without a real carrier.

## Acceptance criteria
- [ ] `SmsSenderPlugin`: `send`, `parseDlr`, `verifyWebhook`, `supports(ctx)`, `healthCheck`, plus **`billableStatuses[]` + `platformFaultExemptions[]`** (F3.5).
- [ ] **`send(msg, providerIdemKey)` accepts a deterministic per-message provider idempotency key** and forwards it to the vendor on every attempt. The contract declares **`supportsIdempotency: boolean`** per provider. *(B2)*
- [ ] If a provider does **not** support an idempotency key, the engine must **not** auto-retry an ambiguous `send()` (timeout/unknown) — it marks the message `unknown` and lets DLR reconcile (the `TRANSPARENT_RETRY` rule only applies to *unambiguous* hard failures).
- [ ] `send()` returns a canonical `ProviderResult { providerRef, acceptedStatus }` mapping to the `accepted` canonical status (F5.3).
- [ ] One real adapter (launch provider) implements it; credentials in secrets manager; **its idempotency-key behavior is verified against the real provider's API**.
- [ ] A **`FakeProvider`** simulates accept + DLR outcomes deterministically (powers F8.5 magic numbers) **and honors the idempotency key** (a repeat key returns the original accept, never a second send).
- [ ] All vendor I/O maps to/from canonical models (`NormalizedMessage`, `CanonicalDlr`).
- [ ] Test: contract conformance suite passes for both adapters, including the **idempotency-key replay** case.

## Design notes
- Lives under `platform/integrations`; SMS-specific bits (sender-IDs, DLR parsing) in the SMS domain.
- The **generic selection/failover engine is PI-2** — PI-1 uses a single configured instance.
- The provider idempotency key is what makes the crash-after-accept retry safe (B2); see F5.2 for the `provider_attempt` row.

## Out of scope (this PI)
- Multi-provider routing, failover, health-based selection.

## Definition of Done
- Provider-contract conformance tests green for real adapter + FakeProvider.
