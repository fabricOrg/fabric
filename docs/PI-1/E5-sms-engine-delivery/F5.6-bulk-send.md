# F5.6 — Basic bulk / batch send

**Epic:** E5 SMS · **Priority:** STRETCH · **Iteration:** 3 (or PI-2)
**Depends on:** F5.2 · **Blocks:** campaigns (PI-2)

## Why
"Bulk SMS" is a core promise. PI-1 needs a *basic* fan-out; throughput/backpressure hardening is
PI-2 (review gap C1).

## Stories
- **US-5.6.1** — As a **developer/tenant**, I can submit many recipients in one request and get per-recipient status, so I can run a simple broadcast.

## Acceptance criteria
- [ ] A batch send accepts N recipients, creates a **`message_batch`** + per-recipient `messages`.
- [ ] Each recipient is rated/reserved/sent independently; **partial failure** is supported (some succeed, some fail).
- [ ] Batch progress + per-recipient status are queryable.
- [ ] Suppression (F7.2) and segmentation (F5.2) applied per recipient.
- [ ] Test: a mixed batch (valid + opted-out + invalid numbers) yields correct per-recipient outcomes.

## Design notes
- Reuses the single-send pipeline per recipient via the queue (BullMQ).
- **PI-2:** provider TPS/throughput caps, backpressure, large-campaign fan-out, fairness.

## Out of scope (this PI)
- High-throughput hardening; scheduling; contact-list integration.

## Definition of Done
- Mixed-batch test; partial-failure handling verified.
