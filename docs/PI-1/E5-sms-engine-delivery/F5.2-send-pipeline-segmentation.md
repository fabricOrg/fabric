# F5.2 — Send pipeline + segmentation

**Epic:** E5 SMS · **Priority:** MUST · **Iteration:** 3
**Depends on:** F5.1, F3.2, F3.4, F7.1, F7.2 · **Blocks:** F6.1 OTP

## Why
The single send path, and the cost is driven by **segmentation/encoding** — get it wrong and we
mis-bill on every message.

## Stories
- **US-5.2.1** — As a **developer**, `POST /v1/sms/send` reliably sends a message and returns a message id + status, charging me correctly.
- **US-5.2.2** — As the **platform**, cost is computed from accurate segment counting before funds are reserved.

## Acceptance criteria
- [ ] Pipeline (order is normative — **suppression before reserve**, S1): **normalize (E.164)** → **encode/segment** → **suppression check** (F7.2) → **rate** (F3.4) → **reserve** (F3.2) → **dispatch** → commit/refund (F3.5). *(Fixes the prior contradiction where suppression ran after reserve.)*
- [ ] Segmentation: **GSM-7** = 160 single / **153** concatenated; **UCS-2** = 70 single / **67** concatenated; a single non-GSM char flips the whole message to UCS-2.
- [ ] Recipient stored as **`subject_id`** (F7.1), never a raw number column.
- [ ] Suppression: a send to an opted-out recipient is **blocked before reserve** (F7.2) — no ledger churn.
- [ ] **Crash-safe dispatch (B2):** in the *same transaction* that sets the message to `sending`, persist a **`provider_attempt`** row carrying a **deterministic provider idempotency key** (e.g. `hash(message_id)`), *before* the network call. On worker retry, the same key is reused (F5.1) → the provider de-dupes → no double-send.
- [ ] **Commit is a compare-and-set:** the charge commits (F3.5) only if the message is still in a non-terminal, non-committed state (guard on `status` + `version`); a retry that finds it already committed is a no-op. Resolution state machine shared with F5.4/F3.3 (B6).
- [ ] **BullMQ** job is configured with bounded `attempts` + backoff and a handler idempotent against a half-written `provider_attempt`.
- [ ] Idempotent on `Idempotency-Key` (F8.2/F1.3) — fingerprint per B5 (F1.3).
- [ ] Test: segment/encoding math (incl. 152-GSM + 1-emoji → 3-segment); blocked-on-opt-out (before reserve); **crash-after-accept retry sends once & commits once**; happy path commits.

## Design notes
- One provider instance in PI-1; failover engine PI-2.
- **Single-provider degradation:** if the sole provider is down/erroring, sends fail cleanly and the
  reservation **refunds** (no funds stuck) — there's no failover in PI-1; that's the motivation for the
  PI-2 failover engine + DLR-trust routing.
- **Ambiguous send (timeout/unknown):** do NOT blindly retry unless the provider supports idempotency (F5.1); mark `unknown` and let DLR + the sweeper (F3.3) resolve.
- Cost estimate surfaced at send (F5.5).

## Out of scope (this PI)
- Scheduling, bulk fan-out throughput hardening (basic batch = F5.6 STRETCH).
