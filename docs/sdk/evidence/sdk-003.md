## Outcome

Fabric now models application-owned, stable-keyed **message definitions** with immutable versions and
per-environment releases. A business user (owner/admin) authors a draft, adds compatible versions, and
publishes to sandbox; a developer sends by stable key. The public `messages.preview` endpoint (and SDK
method) renders a released definition through the **same pure engine a send uses** — so a preview's
body, encoding, segments, and cost equal a subsequent managed send — with **zero side effects**.

The variable schema is a portable, closed JSON-Schema subset validated at every boundary; a breaking
schema change is refused under the same stable key; published version rows are immutable at the
database level (grant-enforced); and all authoring/publishing is confined to a dashboard session or
operator — never a runtime `sk_*` key.

## Acceptance traceability

| Criterion | Evidence |
| --- | --- |
| SDK-003-AC01 (author + publish → immutable version + sandbox release, audited) | `message-definitions.integration` create births a draft + version 1; publish upserts the single sandbox release, flips the definition active, and writes `message_definition.publish`; slice-1 real-Postgres proves `UNIQUE(definition_id, version)` + one-release-per-env. |
| SDK-003-AC02 (member draft/preview, no publish; developer read-only) | **Closed by slice 6b** (`dbfd7d1`). The role gate was replaced by a permission gate: `@app/contracts/permissions` adds `definitions:write` / `definitions:publish`, with member baseline granting write but not publish, owner/admin granting both, and developer-access granting neither (only `api_keys`/`logs`) — so a developer is read-only. The message-definitions BFF routes gate on the permission, not the role (`route.spec.ts` + `[id]/publish/route.spec.ts` + `[id]/versions/route.spec.ts` role/permission matrices); `DefinitionPermissionsProvider` propagates `canWrite` to the authoring UI. `management_requires_session` still rejects `sk_*` at the API. |
| SDK-003-AC03 (edit published content → new version; runtime cannot update published rows) | Slice-1 real-Postgres: runtime role UPDATE/DELETE on `message_definition_versions` is denied (grant REVOKE); `addVersion` inserts a new ordinal, never mutates. |
| SDK-003-AC04 (invalid/missing/extra/oversized/wrong-type vars → bounded field-path errors, no PII/delivery/reservation/outbox) | `message-render` unit: `validatePayload` returns `{path, code}` only, never echoes the value; `message-preview.integration` asserts `messages`/`message_dispatches`/`outbox_events`/`pii_vault` counts unchanged on both valid and invalid preview. |
| SDK-003-AC05 (valid preview render/encoding/segments/cost == a subsequent send) | `message-render` parity test: `previewSms` output equals `encodeAndSegment` + `rateSegments` on the same body; preview and send consume the one `@app/domain` renderer. |
| SDK-003-AC06 (forged application/environment id → rejected, no cross-app/tenant read/write) | `message-definitions.integration` cross-application create denial + RLS isolation; composite containment FKs make a cross-app/tenant release impossible (slice-1 tests). |
| SDK-003-AC07 (template → reviewed draft; original unchanged) | **Closed by slice 6b** (`dbfd7d1`). `templateToDefinitionDraft` (`definition-authoring.ts`) derives a stable key, body, and inferred variables from an existing `SmsTemplate` as a **pure** function — it returns a draft for review in the create dialog and never writes to or mutates the source template. Covered by `definition-authoring.spec.ts`. |
