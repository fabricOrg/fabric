# SDK-002 endpoint-specific webhook delivery evidence

> Status: integrated local release candidate verified - no push or external publication - 2026-07-15

## Outcome

Fabric now materializes one durable delivery for each outbox event and endpoint. Workers commit a
recoverable lease before network I/O, retry endpoints independently, preserve append-only attempt
history, surface pending/dead health, and support owner/admin replay with an audit record. Endpoint
removal is a soft disable, so operational evidence is retained.

Outbound requests resolve and pin the destination immediately before connecting, reject non-public
targets by default, do not follow redirects, validate TLS, apply a ten-second timeout, and never
buffer customer response bodies. The private-network override exists only for deterministic local
tests and must not be configured in deployed environments.

## Acceptance traceability

| Criterion | Evidence |
| --- | --- |
| SDK-002-AC01 | Real-Postgres test registers healthy and failing endpoints, then proves only the failed endpoint is called on retry |
| SDK-002-AC02 | Every retry uses the original outbox event ID; SDK guidance requires unique event-ID deduplication for timeout-after-accept |
| SDK-002-AC03 | Ten failed attempts produce a visible `dead` delivery and append-only attempt rows; the worker emits an error signal |
| SDK-002-AC04 | Replay resets only the selected dead delivery cycle, preserves ten historical attempts, appends the successful eleventh attempt, and records `webhook_delivery.replay` |
| SDK-002-AC05 | Runtime-role queries for another tenant return no delivery and cannot replay it |
| SDK-002-AC06 | An expired `delivering` lease is reclaimed and reaches a terminal state |
