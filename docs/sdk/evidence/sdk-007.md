pushed, no package published, no live path enabled). **All acceptance criteria closed
(AC01–AC05).** The only remaining work is out-of-scope for this item: npm publish (redline) and live

This document consolidates the per-slice notes (the earlier `sdk-007-slice-4a-ii.md`,

## What shipped

Managed Email reuses the existing managed-message engine and the existing direct-email
`FakeEmailProvider` sandbox path — no second execution engine. Email is an **extension** of the
channel-aware model reserved in ADR-0005 (Amendment A1, ratified 2026-07-21), not a rebuild: the
`message_deliveries`/`_attempts` tables were already channel-columned; slice 1 relaxed the two
`channel='sms'` CHECKs to `IN('sms','email')`. Live Email stays absent (SDK-009), gated by the
sandbox-environment assertion and the live redline.

### Migration applicability — PROVEN on a clean DB

`0086` (and the full 86-migration journal) applies from scratch: a throwaway database migrated with

The local dev DB had a **pre-existing `__drizzle_migrations` desync** (records ended at `0082` though

locally. That has been **reconciled** — the four missing rows were inserted with the correct file
hashes + journal timestamps, and `drizzle-kit migrate` now completes `exit 0` on the dev DB.

## Slice 5 — AC04 channel narrowing (2026-07-23)

- **Contracts:** `definitionCatalogEntry.channels` widened from `["sms"]` to `array(messageChannel)`;
  optional `channel` added to `previewMessageRequest` and confirmed on `sendManagedMessageRequest`.
- **API:** the definition-catalog service emits the real per-definition channel; the preview service
  (the single choke point for preview + managed send) rejects a supplied channel that mismatches the
  released definition with 400 `channel_mismatch` — this also **fixed a latent smell**: the managed
  send request's `channel` field was previously accepted and dropped.
- **CLI:** manifest schema accepts `sms|email` channels (was `tuple(['sms'])`).
- **SDK:** `CatalogPreviewOptions` narrows `channel` to the key's released channel; `messages.preview`
  and `send` thread it through; `catalog.type-test.ts` adds an Email key + `@ts-expect-error` fixtures
  proving a channel-unsupported call fails to compile.
- **Verified:** SDK 41 (incl. type-test) + `release:check`; CLI 6; api typecheck; real-Postgres
  preview (new channel-mismatch test) + managed-messages + catalog; OpenAPI current.
